# API документация

### Обращение

Для обращения к api необходимо добавлять префикс с версией, но все методы версионно-нейтральные, сделано это с зададком на будущее. 

**Пример:**
- ``/1/organizations`` - правильное обращение
- ``/organizations`` - неверное обращение

## Endpoint-ы авторизации (/auth)

### ``POST /register``
Принимает запрос на регистрацию нового пользователя, если не возникает ошибок или конфликтов, делается запись в бд.

**Пример запроса:**

В качестве тела запроса используется форма с данными:
Email, Password, FirstName, LastName

При успешном выполнении возвращает 201

### ``POST /login``
Принимает запрос на логин пользователя, если данные совпадают и не происходит конфликтов, создаются access и refresh токены и вставляются в http only куки.

**Пример запроса:**

В качестве тела запроса используется форма с данными:
Email, Password

При успешном выполнении возвращает 200. В куки прикрепляются токены с именами ``access_token`` и ``refresh_token``

### ``GET /activate``
Активирует аккаунт пользователя с использованием кода подтверждения из email.

**Параметры запроса:**
- `email` (query string) - Email пользователя
- `code` (query string) - Код подтверждения из email

При успешном выполнении возвращает 302 и перенаправляет на ``http://localhost:3000``

### ``GET /refresh`` или ``POST /refresh``
Ничего не принимает на вход, пытается восстановить истёкший access токен используя refresh токен из куки.

При успешном выполнении возвращает 200. В куки обновляются токены ``access_token`` и ``refresh_token``

### ``POST /logout`` - необходима авторизация
Ничего не принимает на вход, удаляет токены из куки, делает запрос в базу данных на удаление refresh токена.

Возвращает 205

## Endpoint-ы пользователя (/users)

Все эндпоинты требуют авторизации (JWT токен в куках)

### ``GET /info``
Получает информацию о текущем авторизованном пользователе.

**Формат ответа:**

```json
{
  "email": "user@example.com",
  "firstName": "Имя",
  "lastName": "Фамилия"
}
```

При успешном выполнении возвращает 200

### ``PUT /password``
Изменяет пароль текущего авторизованного пользователя.

**Формат запроса:**

```json
{
  "currentPassword": "старый_пароль",
  "newPassword": "новый_пароль"
}
```

При успешном выполнении возвращает 204

### ``GET /organizations``
Получает организацию текущего авторизованного пользователя.

**Формат ответа:**

```json
{
  "id": "guid",
  "title": "Название организации",
  "description": "Описание",
  "phone": "+7 (999) 123-45-67",
  "address": "г. Москва, ул. Примерная, д. 1",
  "coordinates": {
    "latitude": 55.7558,
    "longitude": 37.6173
  },
  "link": "https://example.com",
  "logoPath": "path/to/logo.jpg",
  "createdAt": "2024-01-01T00:00:00Z",
  "categories": ["Категория 1", "Категория 2"]
}
```

При успешном выполнении возвращает 200

### ``POST /organizations``
Создаёт новую организацию с привязкой к текущему авторизованному пользователю.

**Формат запроса:**

```json
{
  "title": "Название организации",
  "description": "Описание организации",
  "phone": "+7 (999) 123-45-67",
  "city": "Москва",
  "street": "ул. Примерная, д. 1",
  "link": "https://example.com",
  "logoPath": "path/to/logo.jpg",
  "categoryIds": [1, 2, 3]
}
```

**Поля:**
- `title` (обязательное) - Название организации
- `description` (обязательное) - Описание
- `phone` (опциональное) - Телефон
- `city` (опциональное) - Город
- `street` (опциональное) - Улица и дом
- `link` (обязательное) - Ссылка на организацию
- `logoPath` (опциональное) - Путь к логотипу
- `categoryIds` (обязательное) - Список ID категорий

При успешном выполнении возвращает 201

### ``PUT /organizations``
Обновляет организацию текущего авторизованного пользователя.

**Формат запроса:** (аналогичен POST /organizations)

```json
{
  "title": "Обновлённое название",
  "description": "Обновлённое описание",
  "phone": "+7 (999) 123-45-67",
  "city": "Санкт-Петербург",
  "street": "ул. Другая, д. 2",
  "link": "https://example.com",
  "logoPath": "path/to/new-logo.jpg",
  "categoryIds": [2, 3, 4]
}
```

При успешном выполнении возвращает 204

## Endpoint-ы организаций (/organizations)

### ``POST /anonymous``
Создаёт новую организацию без привязки к пользователю (анонимная заявка). Организация создаётся с флагом ``IsActive = false`` и требует активации администратором.

**Формат запроса:** (аналогичен POST /users/organizations)

```json
{
  "title": "Название организации",
  "description": "Описание",
  "phone": "+7 (999) 123-45-67",
  "city": "Москва",
  "street": "ул. Примерная, д. 1",
  "link": "https://example.com",
  "logoPath": "path/to/logo.jpg",
  "categoryIds": [1, 2, 3]
}
```

При успешном выполнении возвращает 201

### ``GET /{id}``
Получает организацию по ID.

**Параметры:**
- `id` (path) - GUID организации

**Формат ответа:** (аналогичен GET /users/organizations)

При успешном выполнении возвращает 200

### ``GET /``
Получает список всех активных организаций.

**Формат ответа:**

```json
{
  "organizations": [
    {
      "id": "guid",
      "title": "Название",
      "description": "Описание",
      "phone": "+7 (999) 123-45-67",
      "address": "г. Москва, ул. Примерная, д. 1",
      "coordinates": {
        "latitude": 55.7558,
        "longitude": 37.6173
      },
      "link": "https://example.com",
      "logoPath": "path/to/logo.jpg",
      "createdAt": "2024-01-01T00:00:00Z",
      "categories": ["Категория 1"]
    }
  ]
}
```

При успешном выполнении возвращает 200

### ``GET /search``
Получает отфильтрованный список активных организаций по заданным критериям.

**Параметры запроса (query string):**
- `searchString` (опциональное) - Поисковая строка (ищет в названии и описании)
- `categoryIds` (опциональное) - Список ID категорий через запятую (например: ``1,2,3``)
- `city` (опциональное) - Фильтр по городу

**Пример запроса:**
```
/1/organizations/search?searchString=благотворительность&categoryIds=1,2&city=Москва
```

**Формат ответа:** (аналогичен GET /)

При успешном выполнении возвращает 200

### ``GET /notactive`` - необходима авторизация (Admin)
Получает список всех неактивных организаций (требующих активации). Доступно только администраторам.

**Формат ответа:** (аналогичен GET /)

При успешном выполнении возвращает 200

### ``PUT /activate/{id}`` - необходима авторизация (Admin)
Активирует организацию по ID. Доступно только администраторам.

**Параметры:**
- `id` (path) - GUID организации

При успешном выполнении возвращает 204

### ``DELETE /{id}`` - необходима авторизация (Admin)
Удаляет организацию по ID. Доступно только администраторам.

**Параметры:**
- `id` (path) - GUID организации

При успешном выполнении возвращает 204

## Авторизация

Большинство эндпоинтов требуют авторизации через JWT токены. Токены передаются через HTTP-only cookies:
- ``access_token`` - действителен 12 часов
- ``refresh_token`` - действителен 7 дней

При работе с защищёнными эндпоинтами браузер автоматически отправляет токены из cookies. Для запросов из других клиентов (например, Postman) необходимо вручную добавить cookie ``access_token`` в запрос.

Для обновления истёкшего access токена используйте эндпоинт ``GET /refresh`` или ``POST /refresh``.
